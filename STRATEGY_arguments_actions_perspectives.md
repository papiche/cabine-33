## 2. Propriété Intellectuelle — Stratégie AGPL + INPI

### 2.1 Ce que l'AGPL v3 protège réellement

L'AGPL-3.0 est le socle choisi pour Astroport.ONE. Ses forces :

- **Clause réseau (§13)** : Toute utilisation "en réseau" (SaaS, API publique) oblige à publier le code source — y compris les modifications. C'est la protection principale contre une centralisation silencieuse.
- **Viralité du copyleft** : Tout logiciel utilisant du code AGPL devient AGPL. Impossible d'injecter du code propriétaire dans le socle.
- **Absence de "SaaS loophole"** : Contrairement à la GPL simple, l'AGPL ferme cette faille.

Ce que l'AGPL ne protège **pas** :
- Les idées, concepts, algorithmes (φ_i, polyèdre de Goldberg, a4l:)
- Les marques nominatives (ATOM4LOVE, UPlanet, ẐEN)
- Le design, l'UX, la charte graphique
- Le modèle économique coopératif

### 2.2 Stratégie INPI — Marques collectives et de certification

*Source : INPI — Marques : cas particuliers*

**Recommandation principale : Marque Collective + Marque de Certification**

La structure G1FabLab, en tant qu'association/coopérative, peut déposer une **marque collective** que ses membres utilisent selon un règlement d'usage. La **marque de certification** (INPI Art. L715-1 à L715-3 CPI) certifie que les produits/services respectent un cahier des charges défini par G1FabLab.

**Application au cas ATOM4LOVE :**

```
Marque de certification "Certifié UPlanet" ou "A4L Certified"
  → Certifie que l'app :
    - Publie son code source (AGPL)
```
